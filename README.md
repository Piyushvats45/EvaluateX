# LLM Evaluation & Prompt Optimization Framework

A modular framework for benchmarking prompts and comparing LLM configurations —
real local model inference, structured evaluation metrics, a REST API, an
interactive demo UI, automated tests, and CI. Every piece runs at **$0 cost**:
open-weight models on your own machine, SQLite for storage, free/open-source
metric libraries, and free-tier hosting for deployment.

## Highlights

- **Real local LLM inference** — DistilGPT-2 / GPT-2 (or any Hugging Face causal-LM) run entirely on your own CPU, no API key, no per-token billing
- **Structured evaluation metrics** — ROUGE-L, BERTScore-style semantic similarity, n-gram diversity, combined into a composite score
- **Modular experiment pipeline** — swap models, prompts, or metrics independently; every prompt × every model config is logged automatically
- **SQLite logging** — every prompt, response, and metric is persisted and queryable after the fact
- **Metric ↔ human agreement analysis** — Pearson/Spearman correlation between automated scores and human ratings, to validate whether cheap automated scoring is a trustworthy proxy for human review
- **REST API** (`api.py`, FastAPI) — deployable behind a URL on any free-tier host
- **Interactive demo UI** (`app.py`, Streamlit) — deployable for free, so you can link a *live, clickable demo* on your resume
- **Automated tests + CI** — `pytest` suite covering metrics, models, and the full pipeline; GitHub Actions runs it on every push

## Architecture

```
llm-eval-framework/
├── app.py                      # Streamlit interactive demo (deploy this for a live link)
├── api.py                      # FastAPI REST service (deploy this behind a URL)
├── run_experiment.py           # CLI entry point for batch experiments
├── human_agreement_demo.py     # demo: metric-vs-human-rating agreement analysis
├── Dockerfile                  # containerized deployment for api.py
├── requirements.txt            # full deps (real models + API + UI + tests)
├── requirements-minimal.txt    # fast install, mock backend only (CI)
├── config/
│   ├── models.yaml             # DEFAULT: real local HuggingFace models
│   └── models.mock.yaml        # offline/CI config, no downloads needed
├── data/
│   └── prompts.json            # structured NLP-task prompt set
├── src/
│   ├── models.py                # pluggable model runners (huggingface / mock)
│   ├── metrics.py                # ROUGE-L, semantic similarity, diversity, composite score
│   ├── database.py               # SQLite logging layer
│   ├── pipeline.py               # orchestrates prompt × model experiment runs
│   └── report.py                 # CSV + self-contained HTML report with charts
├── tests/
│   ├── test_metrics.py
│   ├── test_models.py
│   └── test_pipeline.py
├── .github/workflows/ci.yml    # automated test suite on every push
└── outputs/                    # generated DB, CSV, HTML report (gitignored)
```

## Quickstart

### Option A — real model output (recommended for demoing to others)

```bash
python -m venv venv && source venv/bin/activate      # optional, keeps deps isolated
pip install -r requirements.txt
python run_experiment.py --name "baseline-run" --candidates 2
```

First run downloads DistilGPT-2 and GPT-2 (~350MB total, one-time, free).
Every run after that is instant, offline, and free. Open `outputs/report.html`
to see the comparison charts.

### Option B — instant, zero-download smoke test

```bash
pip install -r requirements-minimal.txt
python run_experiment.py --models config/models.mock.yaml --candidates 2
```

Uses the dependency-free mock backend — good for verifying the pipeline works
before installing torch, or for CI.

## REST API (deploy this for a "hit it with curl" story)

```bash
uvicorn api:app --reload --port 8000
```

```bash
curl -X POST http://localhost:8000/evaluate \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Question: What is the capital of France? Answer:", "reference": "Paris", "backend": "huggingface", "model_name": "distilgpt2"}'
```

Interactive docs at `http://localhost:8000/docs` (auto-generated by FastAPI).

**Deploy it for free** on Render, Fly.io, or a Hugging Face Space with the
Docker SDK, using the included `Dockerfile`:

```bash
docker build -t llm-eval-framework .
docker run -p 8000:8000 llm-eval-framework
```

## Running the tests

```bash
pip install -r requirements-minimal.txt   # or requirements.txt
pytest tests/ -v
```

Tests use the mock backend exclusively, so the whole suite runs in seconds
with no model downloads and no network access — this is also what CI runs
on every push (see `.github/workflows/ci.yml`).

## Human-in-the-loop agreement check

```bash
python human_agreement_demo.py
```

Attaches simulated human ratings to specific (prompt, model) pairs and
reports Pearson/Spearman correlation against the automated composite score —
the same reliability check used to validate automated scoring against human
judgment at scale.

## Extending the framework

- **New prompt / task type** — add entries to `data/prompts.json`
- **New model** — add an entry to `config/models.yaml` (any HF causal-LM model id works)
- **New metric** — add a function to `src/metrics.py`, fold it into `score_response()`
- **New report visualization** — add a chart function to `src/report.py`

Because prompts, models, metrics, and reporting are fully decoupled modules,
iterating on a prompt engineering strategy is: edit `data/prompts.json` or
`config/models.yaml`, re-run `run_experiment.py`, diff the new report
against the old one.

## What to highlight in an interview

- **Systems thinking**: pluggable backends (`models.py`) and a metrics module
  with automatic graceful fallbacks (BERTScore → TF-IDF cosine → Jaccard when
  heavier dependencies aren't available) — the framework degrades gracefully
  instead of breaking.
- **Evaluation rigor**: composite scoring is configurable and decomposed into
  interpretable sub-metrics; human-agreement analysis quantifies whether the
  automated proxy can be trusted.
- **Production instincts**: tests + CI, a deployable REST API, containerization,
  and a live demo — not just a notebook.
- **Cost-consciousness**: every design decision (open-weight local models,
  SQLite, free-tier hosting) was made to keep the system $0 to run and $0 to
  demo.
